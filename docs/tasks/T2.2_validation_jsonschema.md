# T2.2 — Validation des schemas avec `jsonschema`

**Statut : Terminé** (implémenté le 12/10/2026, non commité à la demande du concepteur)

## Objectif

Valider les charges utiles brutes retournées par l'API data.gouv.fr **avant tout traitement**, afin que les fonctions de T3.x reçoivent des données garanties conformes. Tout écart de schéma produit un échec propre (`echec_technique`), jamais une exception non gérée.

## Décisions de conception

1. **Séparation stricte** : les schémas de réponses API vivent dans `contrats/schemas_api/`, séparés des contrats d'outils (`contrats/<outil>.json`) qui restent la source de vérité pour le function calling Mistral.
2. **Échec propre systématique** : `valider_reponse_api()` ne lève jamais d'exception pour des données non conformes, ni pour un outil inconnu ou un schéma illisible — tout est converti en `ResultatValidation` avec statut `echec_technique`.
3. **Messages d'erreur avec chemin JSON pointer** (ex. `/data/0/resources/0/filesize`) pour un diagnostic rapide.
4. **`additionalProperties: true`** : l'API data.gouv.fr ajoute régulièrement des champs ; la validation ne doit pas casser sur des champs non utilisés par l'application.
5. **Marqueur `reseau` non requis** : TU-34..TU-38 utilisent des fixtures ; aucun test T2.2 ne nécessite le réseau.
