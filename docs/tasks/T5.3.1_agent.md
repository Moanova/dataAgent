# Suivi T5.3.1 — Création (et destruction) de l'agent Mistral

## Statut
- **T5.3.1** : ✅ Terminé (14/10/2026) — test réel validé en local par le concepteur

## Contexte
Décisions actées avec le concepteur après comparatif des options :
- **Agent éphémère** par exécution (créé/détruit par code via l'API beta) plutôt qu'agent persistant : la configuration (prompt, modèle, outils) vit dans le dépôt, conformément à l'invariant du contrat global (« le code refuse de démarrer si les sources divergent »).
- **Classe beta du SDK** (`client.beta.agents`) plutôt qu'appels REST directs : nécessite `mistralai>=3.2.0` (pin dans `requirements.txt`).
- **Garde-fou** : un `MISTRAL_AGENT_ID` optionnel peut désigner un agent persistant ; il n'est réutilisé que s'il est strictement conforme (modèle, empreinte sha256 du prompt, ensemble d'outils) ; toute divergence → création éphémère + journalisation. L'agent persistant réutilisé n'est jamais détruit par le flux.

## Implémentation (`src/agent/agent.py`)
- `charger_outils()` : charge les 4 contrats depuis `contrats/manifeste.json`, refuse toute divergence manifeste/fichier/function.name (invariant contrat_global).
- `creer_agent(id_execution, client=None)` : clé `MISTRAL_API_KEY` (jamais dans le code), modèle `MISTRAL_MODELE` (défaut `mistral-small-latest`), `beta.agents.create(model, name="openDataAgent-<id_execution>", instructions=PROMPT_SYSTEME, tools, metadata={id_execution, projet})` ; retour normalisé `{statut, message, donnees:{agent}}`.
- `detruire_agent(agent)` : `beta.agents.delete` ; idempotent (404 → succès) ; suggestion `nettoyer_agents_orphelins` en cas d'erreur réseau.
- `nettoyer_agents_orphelins(client)` : listage + suppression des seuls agents du projet (préfixe de nom ou `metadata.projet`) — recovery après crash entre create et finally.
- `PROMPT_SYSTEME` : version minimale structurée (rôle, français, 4 outils, format {statut, message, donnees}, intégrité des identifiants). Le contenu riche A1–A4 est T5.3.4.
- Journalisation structlog de tous les événements (`agent_cree`, `agent_detruit`, `agent_persistant_reutilise`, `agent_persistant_divergent`, etc.).

## Notes d'environnement
- Sandbox : deux installations de `mistralai` coexistent (namespace) — l'import `from mistralai import Mistral` peut échouer au profit de `from mistralai.client import Mistral` ; le module gère les deux par try/except. En installation propre (locale), l'import canonique fonctionne.
- API beta : surface susceptible d'évoluer — version pinée `mistralai>=3.2.0` dans `requirements.txt`.
