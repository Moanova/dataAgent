## Objectif
Rendre le chaînage manuel (`list` puis `download`/`query`) possible en mode CLI : chaque commande étant un processus indépendant, l'inventaire en mémoire mourait avec lui et `--id-execution` n'avait qu'un rôle de trace. Design acté en séance du 14/10.

## Implémentation
- `src/core/resources.py` — deux fonctions additives (mécanisme interne inchangé, TI-14b reste vert) :
  - `decharger_inventaire()` : copie sérialisable de l'inventaire (métadonnées de jeu dénormalisées par ressource : `id_jeu`, `organisation`, `licence` — le dump suffit, pas besoin de `_jeu_courant`) ;
  - `charger_inventaire(donnees)` : fusion enrichissante (jamais d'écrasement), retourne le nombre de ressources ajoutées.
- `src/main.py` :
  - `REPERTOIRE_EXECUTIONS = data/executions/`, `_chemin_inventaire()`, `_charger_inventaire_persiste()` (silencieux si absent, avertissement jaune si illisible), `_persister_inventaire()` (écriture simple `json.dump`, pas de verrou — usage mono-utilisateur) ;
  - chargement dans les 5 commandes (après `configure_logging`) ;
  - persistance après `list` réussi (seule commande productrice) ;
  - affichage `id_execution : <id>` sur stderr en sortie non-JSON (les sorties `--json` restent parsables) — l'id auto-généré est désormais observable et rejouable.
- `docs/architecture/contrat_global.md` — convention 1 précisée : la chaîne s'étend, en mode CLI, aux exécutions antérieures réactivées sous le même `id_execution` ; mode agentique inchangé (mémoire seule).
- `docs/README.md` — section « ⚠️ piége list→download » réécrite en « 🔗 chaînage des commandes » : usage, enrichissement cumulatif, isolation par id, id auto affiché, convention 1.

## Décisions de conception (actées avec le concepteur)
- Fichier par exécution (`data/executions/<id>/inventaire.json`), pas de registre global — isole des flux parallèles, prépare T7.2 (nettoyage).
- Écriture simple, pas de verrou ni d'atomicité (usage mono-utilisateur).
- Affichage de l'id automatique : sans lui, l'id auto serait irrattrapable entre deux commandes ; avec lui, `--id-execution` manuel devient une commodité de nommage, pas une fonctionnalité distincte.

## Tests
- `tests/unit/test_resources.py` : round-trip décharger/charger (métadonnées complètes, rechargement intégal), enrichissement cumulatif sans écrasement.
- `tests/unit/test_cli.py` : chaînage complet `list --id-execution X` → fichier écrit → `_inventaire` vidé → `download --id-execution X` réussit et affiche l'id ; sans inventaire persisté, `ressource_introuvable` (convention 1) et aucun fichier écrit.
