## Implémentation

### `src/agent/outils.py` — exécution des tool_calls
- `TABLE_OUTILS` : dispatch des 4 outils vers `src/core/` (rechercher_jeux, lister_ressources, interroger_ressource, telecharger_brut).
- `executer_outil(nom, arguments, id_execution)` : décodage des arguments (dict ou chaîne JSON — format tool_call), validation des arguments obligatoires, filtrage des options, appel de la fonction cœur ; outil inconnu, arguments invalides ou exception cœur → statut normalisé (`erreur_parametres` / `echec_technique`), jamais d'exception vers l'agent.

### `src/agent/boucle.py` — boucle de conversation
- `boucle_conversation(agent, message_utilisateur, plafond=None, id_execution)` :
  - envoi via `client.agents.complete(agent_id, messages)` ;
  - itération : tant que la réponse contient des `tool_calls`, exécution via `executer_outil` et renvoi du résultat normalisé en message `tool` (JSON `{statut, message, donnees}`, `tool_call_id`) ;
  - réponse finale sans tool_call → succès avec `reponse_agent`, `nb_invocations`, `plafond` ;
  - **plafond d'invocations** (défaut 10, CA-11 ; `PLAFOND_INVOCATIONS` dans l'environnement) : arrêt propre, synthèse partielle ;
  - erreur API → `echec_technique` avec invocations effectuées.
- Formats tolérés : réponses SDK objets ou dicts, `arguments` en chaîne JSON.
- **Journalisation sans blocage (TA-02, décision du concepteur)** : événements `boucle_debut`, `boucle_outil_invoque` (outil, arguments, tour), `boucle_outil_resultat` (statut), `boucle_reponse_finale`, `boucle_plafond_atteint`, `boucle_erreur_api` — la propriété d'ordre se vérifie par rejeu des journaux ; aucun blocage actif (le cœur refuse déjà les identifiants hors chaîne).
