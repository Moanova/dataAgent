## Décisions de conception actées (vérifiées en réel avant implémentation)
- **Deux URLs de base** : catalogue (`www.data.gouv.fr/api/1/`) et tabulaire (`tabular-api.data.gouv.fr/api`, constante `TABULAR_API_URL` surchargeable par env). L'outil 3 parle au second serveur.
- **`taille_page` max 50** (le contrat disait 100 ; l'API tabulaire refuse au-delà de 50) — corrigé dans doc d'architecture, contrat JSON et modèle Pydantic.
- **Détection `api_tabulaire`** incluse (elle était codée false depuis T3.2.1) : pendant l'inventaire, ping `GET /resources/{rid}/` pour chaque ressource classée `fichier_tabulaire` ; 200 = indexée, 404/échec = non indexée (défaut sûr). C'est un fait vérifiable par HTTP → responsabilité du code, l'agent ne fait que lire le champ (cf. contrat_global : « le code exécute : tous les appels HTTP »).
- **Colonnes** : depuis la première ligne de `data` ; repli sur `profile/` si `data` vide (page hors limites ou table vide) — un seul appel supplémentaire dans ce seul cas.
- **Sondage réel préalable** (anti-divergence v1/v2) : endpoints, opérateurs (`exact/contains/less/greater/strictly_less/strictly_greater`), tri (`__sort=asc|desc`), pagination, format de réponse (`data/links/meta`) — tout vérifié sur l'API de production, fixture réelle capturée (films CNC, 95 764 lignes).
